# Using CMBuilder `.npz` output in SAX

This guide explains how to take the `.npz` file generated by CMBuilder and use it inside a **SAX** circuit simulation. It covers the file format, the port naming convention, how multi-polarization is handled, and the physical constraints that the `.npz` must satisfy.

---

## 1. What is SAX and why use it

[SAX](https://flaport.github.io/sax/) is a Python library for S-parameter-based circuit simulation of photonic networks. It lets you connect individual component models (described by their S-parameters) into a circuit and compute the overall transfer function of the assembled system.

The typical workflow is:

1. Export each component from CMBuilder as a `.npz` file.
2. Wrap the `.npz` into a SAX-compatible model function.
3. Declare the circuit topology (instances, connections, ports).
4. Call the circuit to evaluate S-parameters at the desired wavelengths.

---

## 2. The `.npz` file format

### 2.1 Contents

A `.npz` generated by CMBuilder always contains:

| Key | Type | Description |
|---|---|---|
| `wavelengths` | `float[N]` | Wavelength array in **µm** |
| `"oOUT_mMODE_OUT,oIN_mMODE_IN"` | `complex[N]` | One complex S-parameter array per path |

The complex values encode both magnitude and phase: `S = magnitude × exp(j·phase)`.

### 2.2 Port naming convention

Each S-parameter key is a string of the form:

```
oOUT_mMODE_OUT,oIN_mMODE_IN
```

where:

- `oOUT` — **output** physical port number, e.g. `o3` = port 3.
- `mMODE_OUT` — **output** mode index (0-based), e.g. `m0` = TE0, `m1` = TM0.
- `oIN` — **input** physical port number, e.g. `o1` = port 1.
- `mMODE_IN` — **input** mode index (0-based).

So the key `o3_m0,o1_m1` means: *signal entering at port 1 in mode TM0 (m1), exiting at port 3 in mode TE0 (m0)*. This corresponds to S-parameter $S_{31}^{TM0 \to TE0}$.

> **Why `_m` and not `@`?**  
> gplugins internally uses the `@` separator (`o3@0,o1@1`). CMBuilder's parser stores files using `_m` instead, because `@` causes issues with some numpy and filesystem operations. The conversion between the two is handled in the loading step described below.

### 2.3 Example: summary of a directional coupler

```
ID      : a327154896
Cell    : directional_coupler_v1
λ range : 1.5238 – 1.5738 µm  (70 points)

S-param key                               |S| min   max   mean
----------------------------------------------------------------------
  o3_m0,o1_m0                             0.675  0.711  0.693
  o3_m1,o1_m0                             0.136  0.145  0.140
  o3_m0,o1_m1                             0.136  0.145  0.140
  o3_m1,o1_m1                             0.675  0.711  0.693
  ...
```

Reading the first two lines: for an input at port 1 in TE0 (`o1_m0`), roughly 69% of power exits at port 3 in TE0 (`o3_m0`) and 14% at port 3 in TM0 (`o3_m1`) — the cross-polarization crosstalk.

## 3. Loading the `.npz` and building a SAX model

### 3.1 Why `gsax.read.model_from_npz` does not work here

gplugins provides a convenience function `gsax.read.model_from_npz()` to load `.npz` files directly into a SAX model. However, it expects port names using the `@` separator (`o1@0`), while CMBuilder uses `_m` (`o1_m0`). Calling it on a CMBuilder file will raise an error.

The solution is a custom loader that reads the `.npz` and translates the port names on the fly.

### 3.2 Custom model loader

```python
import numpy as np
import jax.numpy as jnp

def model_from_npz_multimodal(npz_path):
    """
    Builds a SAX-compatible model function from a CMBuilder .npz file.
    Translates port names from 'oX@N' (CMBuilder) to 'oX_mN' (SAX netlist).
    The npz file that comes from CMBUILDER already has 'oX_mN' but in case a npz
    file is stored with the gplugings format, it converts it to SAX format.
    Interpolates S-parameters to any requested wavelength array.
    """
    sp = np.load(npz_path)
    wl_ref = sp["wavelengths"]
    s_keys = [k for k in sp.files if k != "wavelengths"]

    def model(wl=wl_ref):
        S = {}
        for key in s_keys:
            port_out, port_in = key.split(",")
            data = sp[key]
            # Interpolate real and imaginary parts separately
            S_interp = (
                jnp.interp(wl, wl_ref, jnp.array(data.real)) +
                1j * jnp.interp(wl, wl_ref, jnp.array(data.imag))
            )
            S[(port_in, port_out)] = S_interp
        return S

    return model
```

The model function accepts a `wl` array and returns an `SDict` — a dictionary keyed by `(port_in, port_out)` tuples — which is exactly what SAX expects.

### 3.3 Loading the file and inspecting available ports

```python
dc_model = model_from_npz_multimodal("directional_coupler_v1_a327154896.npz")

sp = np.load("directional_coupler_v1_a327154896.npz")
wl = sp["wavelengths"]

# List all unique ports in the file
ports = sorted(set(
    p for k in sp.files if k != "wavelengths"
    for p in [k.split(",")[0], k.split(",")[1]]
))
print("Available ports:", ports)
# → ['o1_m0', 'o1_m1', 'o2_m0', 'o2_m1', 'o3_m0', 'o3_m1', 'o4_m0', 'o4_m1']
```

Each `oX_m0` is the TE0 channel of physical port X, and `oX_m1` is the TM0 channel. Every physical port has one entry per polarization mode.

## 4. Multi-polarization handling

### 4.1 How polarization is encoded in port names

SAX treats each `(port, mode)` pair as a completely independent signal channel. There is no automatic coupling between modes — all mode mixing must be encoded explicitly in the S-parameter matrices stored in the `.npz`.

For a component with 4 physical ports and 2 polarizations (TE0, TM0), the port list in the `.npz` is:

```
o1_m0  ← port 1, TE0
o1_m1  ← port 1, TM0
o2_m0  ← port 2, TE0
o2_m1  ← port 2, TM0
o3_m0  ← port 3, TE0
o3_m1  ← port 3, TM0
o4_m0  ← port 4, TE0
o4_m1  ← port 4, TM0
```

The full S-parameter matrix therefore has `(4 ports × 2 modes)² = 64` entries. CMBuilder stores only the non-zero or physically meaningful ones.

### 4.2 Connecting components in the circuit netlist

When building the SAX circuit, every physical wire between two components must be declared **separately for each polarization**. A single-mode connection is not enough — if you connect TE0 but forget TM0, the TM0 signal has nowhere to go and the simulation produces physically incorrect results.

Example — connecting the upper arm of a directional coupler to a waveguide:

```python
"connections": {
    # Upper arm — both polarizations must be connected
    "coup1,o3_m0": "wg_up,in0_TE0",   # TE0 channel
    "coup1,o3_m1": "wg_up,in0_TM0",   # TM0 channel
    "wg_up,out0_TE0": "coup2,o1_m0",
    "wg_up,out0_TM0": "coup2,o1_m1",
},
```

### 4.3 Naming the circuit's external ports

The `ports` block maps internal `(instance, port_mode)` pairs to human-readable external port names. The convention used in the example is:

```
in_TE0_1   → input, TE0 polarization, physical port 1
in_TM0_1   → input, TM0 polarization, physical port 1
out_TE0_1  → output, TE0 polarization, physical port 1
out_TM0_2  → output, TM0 polarization, physical port 2
```

```python
"ports": {
    "in_TE0_1":  "coup1,o1_m0",
    "in_TM0_1":  "coup1,o1_m1",
    "in_TE0_2":  "coup1,o2_m0",
    "in_TM0_2":  "coup1,o2_m1",
    "out_TE0_1": "coup2,o3_m0",
    "out_TM0_1": "coup2,o3_m1",
    "out_TE0_2": "coup2,o4_m0",
    "out_TM0_2": "coup2,o4_m1",
},
```

## 5. Physical constraint: input and output polarizations must be consistent

This is the most important correctness requirement when preparing a `.npz` file.

**The rule:** for every polarization mode that appears as an output, the same mode must also appear as an input, and vice versa.

### Why this matters

SAX connects components port-by-port. When it joins `coup1,o3_m1` (a TM0 output) to `wg_up,in0_TM0` (a TM0 input), it assumes that the component on the other end — the waveguide — has a TM0 response at that port. If the `.npz` of the waveguide only contains TE0 S-parameters, SAX will either error out or silently assign a zero response to the TM0 channel, which has no physical meaning.

More concretely:

- If the `.npz` contains `o3_m0,o1_m0` (TE0 in → TE0 out), it **must** also contain `o3_m1,o1_m1` (TM0 in → TM0 out) if TM0 is going to be used anywhere in the circuit that connects to that component.
- If cross-polarization conversion exists (e.g. `o3_m1,o1_m0`, TE0 in → TM0 out), then the reverse path `o3_m0,o1_m1` should also be present for reciprocity, unless the component is deliberately non-reciprocal.
- A `.npz` that only covers TE0 cannot be connected to a circuit port carrying TM0 — the result would be a mode mismatch with no physical basis.

### Practical checklist before using a `.npz` in SAX

| Check | What to verify |
|---|---|
| Symmetric mode coverage | For every `oX_mN` that appears as output, `oX_mN` also appears as input. |
| No orphan modes | No output mode exists without a corresponding input mode in the same file. |
| Length consistency | All S-parameter arrays have the same length as `wavelengths`. |
| Wavelength overlap | The `wavelengths` range of all components in the circuit overlaps sufficiently. |

## 6. Full example: MZI built from two directional couplers

This example constructs a Mach-Zehnder interferometer from two directional couplers and two waveguides, preserving both TE0 and TM0 polarizations throughout.

### Circuit definition

```python
s_circ, info = sax.circuit(
    netlist={
        "instances": {
            "coup1":    "dc",
            "coup2":    "dc",
            "wg_up":    "waveguide",
            "wg_down":  "waveguide",
        },
        "connections": {
            # Upper arm — TE0 and TM0
            "coup1,o3_m0": "wg_up,in0_TE0",
            "coup1,o3_m1": "wg_up,in0_TM0",
            "wg_up,out0_TE0": "coup2,o1_m0",
            "wg_up,out0_TM0": "coup2,o1_m1",
            # Lower arm — TE0 and TM0
            "coup1,o4_m0": "wg_down,in0_TE0",
            "coup1,o4_m1": "wg_down,in0_TM0",
            "wg_down,out0_TE0": "coup2,o2_m0",
            "wg_down,out0_TM0": "coup2,o2_m1",
        },
        "ports": {
            "in_TE0_1":  "coup1,o1_m0",
            "in_TM0_1":  "coup1,o1_m1",
            "in_TE0_2":  "coup1,o2_m0",
            "in_TM0_2":  "coup1,o2_m1",
            "out_TE0_1": "coup2,o3_m0",
            "out_TM0_1": "coup2,o3_m1",
            "out_TE0_2": "coup2,o4_m0",
            "out_TM0_2": "coup2,o4_m1",
        },
    },
    models={"dc": dc_model, "waveguide": waveguide},
)
```

### Waveguide model (independent per polarization)

```python
def waveguide(wl=1.55, neff=1.6072, length=10.0, loss=0.0) -> sax.SDict:
    phase = 2 * jnp.pi * neff * length / wl
    transmission = 10 ** (-loss * length / 20) * jnp.exp(1j * phase)
    return sax.reciprocal({
        ("in0_TE0", "out0_TE0"): transmission,
        ("in0_TM0", "out0_TM0"): transmission,
    })
```

Note that both polarizations are handled independently — TE0 and TM0 accumulate the same phase (same `neff` here) but can be given different effective indices if needed.

### Evaluating and plotting

```python
l1 = 10
l2 = l1 + 10.4

s_test = s_circ(
    wg_up={"length": l1, "neff": 2.15, "wl": wl, "loss": 0},
    wg_down={"length": 2 * l2, "neff": 2.15, "wl": wl, "loss": 0},
)

entradas = ["in_TE0_1", "in_TM0_1"]
salidas  = ["out_TE0_1", "out_TM0_1", "out_TE0_2", "out_TM0_2"]

fig, axes = plt.subplots(1, len(entradas), figsize=(13, 5))
for ax, entrada in zip(axes, entradas):
    for i, salida in enumerate(salidas):
        par = (entrada, salida)
        if par not in s_test:
            continue
        H = np.abs(np.array(s_test[par])) ** 2
        ax.plot(wl, H, label=salida)
    ax.set_title(f"Input: {entrada}")
    ax.set_xlabel("Wavelength (µm)")
    ax.set_ylabel("|H|²")
    ax.legend(fontsize=8)
    ax.grid(True)

plt.tight_layout()
plt.show()
```

`s_test` is a dictionary keyed by `(input_port, output_port)` tuples using the human-readable names defined in `ports`. Accessing `s_test[("in_TE0_1", "out_TM0_2")]` gives the complex transfer function from TE0 input at port 1 to TM0 output at port 2, evaluated at all wavelengths in `wl`.
